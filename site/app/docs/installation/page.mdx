# Installation

Ragdoll builds with a stable Rust toolchain and nothing else. There are no system libraries to install, no `pkg-config`, and no configure step.

## Requirements

- **A recent stable Rust toolchain.** The workspace uses the 2024 edition and language and library features stabilized in Rust 1.88, so older compilers cannot build it; CI uses the current stable release. Install it with [rustup](https://rustup.rs).
- **A 64-bit target.** `aarch64` gets the NEON kernels; `x86_64` gets the AVX2 kernels when the CPU has AVX2, and the scalar reference paths otherwise.
- **Optional:** `ffmpeg` and `ffprobe` on your `PATH` to run the interop tests (see [Contributing](/docs/contributing/)) or [`bench --compare-ffmpeg`](/docs/cli/bench/).

## Install the CLI

Install the `ragdoll` binary straight from the repository:

```sh
cargo install --git https://github.com/oddurs/ragdoll ragdoll-cli
```

`ragdoll-cli` is the package name; the binary it installs is called `ragdoll`. Check that it runs and see which SIMD level it detected:

```sh
ragdoll --version
```

```text
ragdoll 0.1.0 (x86_64 AVX2 (256-bit) | 2 P-cores + 2 E-cores)
```

That is a four-core Linux VM. On Apple Silicon the SIMD level reads `aarch64 NEON (128-bit x 32 ASIMD)` and the core counts come from the performance and efficiency clusters; on Linux, which reports no core types, the logical cores are split in half.

## Build from source

Clone the repository if you want to run the tests, the self-test, or work on the code:

```sh
git clone https://github.com/oddurs/ragdoll.git
cd ragdoll
cargo build --release
./target/release/ragdoll --help
```

The release profile uses fat LTO and a single codegen unit, so the first build takes a minute or two. For a faster edit-and-run loop you can relax both from the command line:

```sh
CARGO_PROFILE_RELEASE_LTO=false CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16 \
  cargo build --release
```

## Verify your build

Run the test suite, then the differential self-test. The self-test runs the hot SIMD kernels against their scalar references on your hardware and prints throughput for both:

```sh
cargo test --workspace
cargo run --release -- self-test
```

The interop tests compare against FFmpeg and fail when `ffmpeg` or `ffprobe` is missing; set `RAGDOLL_ALLOW_MISSING_TOOLS=1` to skip them instead.

Every kernel row should report `EXACT` in its last column. If one does not, please [open an issue](https://github.com/oddurs/ragdoll/issues) with the output and your CPU model.

## Use the crates as a library

The crates are not yet published to crates.io. Until 1.0, depend on them from git and pin a revision:

```toml title="Cargo.toml"
[dependencies]
ragdoll-format = { git = "https://github.com/oddurs/ragdoll", rev = "<commit>" }
ragdoll-core = { git = "https://github.com/oddurs/ragdoll", rev = "<commit>" }
```

See [Library usage](/docs/library/) for examples.
