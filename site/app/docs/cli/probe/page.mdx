# ragdoll probe

Inspect a media file's container and tracks. `probe` parses headers and sample tables only; it never decodes a frame, so it typically finishes in tens to hundreds of microseconds.

```sh
ragdoll probe <FILE> [--gop-map] [--json]
```

## Options

| Option | Description |
| :-- | :-- |
| `<FILE>` | Input file, or `-` for stdin. The container is detected from its contents. |
| `--gop-map`, `-g` | Print a per-packet waterfall showing I and P frame sizes grouped by GOP (first 32 packets). |
| `--json`, `-j` | Print a JSON object instead of the table. |

## What it reports

- **Container** and file size, plus how long the probe took.
- **GOP count**, computed from keyframe flags in the sample index.
- **H.264 profile and level**, parsed from the SPS, when the first video track is H.264.
- **Per track:** codec, dimensions and frame rate (as both a decimal and an exact rational), pixel format, CICP colorimetry (primaries, transfer, matrix, range), sample rate, channel count and layout, sample format, and the number and total size of packets.
- **Bitrate sparkline** over packet sizes.

ragdoll probe sample.mp4 --gop-map

## JSON output

```sh
ragdoll probe sample.mp4 --json
```

```json
{
  "path": "sample.mp4",
  "container": "mp4/isobmff",
  "file_size": 7844139,
  "probe_time_us": 42.750,
  "gop_count": 10,
  "h264_profile": "Constrained Baseline (level 4.0)",
  "tracks": [
    {"index": 0, "type": "video", "codec": "h264", "width": 1280, "height": 720, "fps": 30.0000, "pixel_format": "yuv420p", "samples": 60}
  ]
}
```

Audio tracks carry `sample_rate`, `channels` and `sample_format` in place of the video fields. Subtitle tracks carry only `index`, `type`, `codec` and `samples`.

## Supported inputs

MP4 / MOV, Matroska, WebM, MPEG-TS (188, 192 and 204-byte packets), YUV4MPEG2, WAV / RF64, FLAC, WebVTT and SubRip. See [Formats & codecs](/docs/formats/).

<Callout kind="warning" title="Known issue">
When an MPEG-TS stream arrives on stdin, `probe -` can report the wrong video dimensions. Probing the same stream from a file is unaffected.
</Callout>
