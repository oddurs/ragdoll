# ragdoll probe

Inspect a media file's container and tracks. `probe` parses headers and sample tables only; it never decodes a frame, so it typically finishes in tens to hundreds of microseconds.

```sh
ragdoll probe <FILE> [--gop-map] [--json]
```

## Options

| Option | Description |
| :-- | :-- |
| `<FILE>` | Input file, or `-` for stdin. The container is detected from its contents. |
| `--gop-map`, `-g` | Print a per-packet waterfall showing I and P frame sizes grouped by GOP (first 32 packets). |
| `--json`, `-j` | Print a JSON object instead of the table. |

## What it reports

- **Container** and file size, plus how long the probe took.
- **GOP count.** For MP4 it is computed from the video track's keyframe flags. For Matroska and MPEG-TS it counts keyframe packets on every track, so audio packets inflate it; for FLAC and Ogg it is the packet count.
- **H.264 profile and level**, parsed from the SPS, when an MP4 file has an H.264 video track.
- **Per track:** codec, dimensions and frame rate (as both a decimal and an exact rational), pixel format, CICP colorimetry (primaries, transfer, matrix, range), sample rate, channel count and layout, sample format, and the number and total size of packets.
- **Bitrate sparkline** over packet sizes.

## Example

`av.mp4` is a two-second 720p clip from [`synth`](/docs/cli/synth/) with an AAC track added:

```sh
ragdoll probe av.mp4 --gop-map
```

## JSON output

```sh
ragdoll probe av.mp4 --json
```

```json
{
  "path": "av.mp4",
  "container": "mp4/isobmff",
  "file_size": 171376,
  "probe_time_us": 203.107,
  "gop_count": 4,
  "h264_profile": "Constrained Baseline (level 4.0)",
  "tracks": [
    {"index": 0, "type": "video", "codec": "h264", "width": 1280, "height": 720, "fps": 30.0000, "pixel_format": "yuv420p", "samples": 60},
    {"index": 1, "type": "audio", "codec": "aac", "sample_rate": 48000, "channels": 2, "sample_format": "s16le", "samples": 94}
  ]
}
```

Audio tracks carry `sample_rate`, `channels` and `sample_format` in place of the video fields. Subtitle tracks carry only `index`, `type`, `codec` and `samples`. `h264_profile` is `null` when there is nothing to report.

## Supported inputs

MP4 / MOV, Matroska, WebM, MPEG-TS (188, 192 and 204-byte packets), YUV4MPEG2, WAV / RF64, FLAC, Ogg (Opus and FLAC), PNG, JPEG, PPM, WebVTT and SubRip. See [Formats & codecs](/docs/formats/).
