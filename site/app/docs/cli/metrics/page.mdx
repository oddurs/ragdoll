# ragdoll metrics

Measure how closely a distorted video matches a reference. Frames are compared pairwise in decode order, and per-frame scores are averaged.

```sh
ragdoll metrics <REFERENCE> <DISTORTED> [--json]
```

The reference comes first. Either input can be any video `transcode` decodes, such as MP4, Matroska, MPEG-TS or Y4M. Both inputs must have the same dimensions; scale one with [`transcode --scale`](/docs/cli/transcode/) first if they don't. Mismatched sizes are not yet reported as a clean error: the process aborts.

## Metrics

| Metric | Planes | Description |
| :-- | :-- | :-- |
| **PSNR** | Y, U, V, average, 6:1:1 | Peak signal-to-noise ratio in dB. The 6:1:1 value weights luma six times each chroma plane, as is conventional for codec comparisons. |
| **SSIM** | Y, average | Structural similarity over 8×8 windows, also reported in dB as `-10·log10(1 − SSIM)`. |
| **MS-SSIM** | Y | Five-scale multi-scale SSIM with the standard Wang et al. weights. |
| **VMAF-Lite** | Y | A fast approximation of VMAF built from a VIF-style information-fidelity term. Useful for tracking changes; it is not a substitute for libvmaf scores. |

All metrics operate on 8-bit planes. They use NEON kernels on `aarch64`; on `x86_64`, the sum-of-squared-error (PSNR) and SSIM statistics kernels use AVX2.

Both inputs are decoded a batch at a time and compared in waves of 30 frames, so memory stays within the pipeline's budget however long the videos are.

## Example

```sh
ragdoll transcode sample.mp4 q30.mp4 --qp 30
ragdoll metrics sample.mp4 q30.mp4
```

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ RAGDOLL PERCEPTUAL QUALITY METRICS (60 frames in 576.42 ms / 104.1 fps)
├──────────────────────────────────────────────────────────────────────────────┤
│ PSNR (dB)     : Y=49.11 dB | U=48.14 dB | V=47.76 dB | Avg=48.65 dB (6:1:1=48.82 dB)
│ SSIM (8x8)    : Y=0.99522 (23.19 dB) | Avg=0.99513 | 5-Scale MS-SSIM=0.99618
│ VMAF-Lite     : 86.05 / 100.0
└──────────────────────────────────────────────────────────────────────────────┘
```

Identical inputs report `inf` for PSNR and SSIM in dB. In `--json` output, infinite PSNR and SSIM dB values are written as `99.99` so the document stays valid JSON.

If the two inputs have different frame counts, only the first `min(a, b)` frames are compared.
