# ragdoll-core

The shared vocabulary of the workspace: time, color, frames, packets, bit I/O, checksums, errors, power management and SIMD dispatch. It has no dependencies.

[Source](https://github.com/oddurs/ragdoll/tree/main/crates/ragdoll-core)

## Time

`Rational64` is a reduced `num/den` pair. Reduction uses continued-fraction convergents with semiconvergent clamping (the same algorithm as FFmpeg's `av_reduce`), and `Rational64::from_f64` recovers a rational from a float the way `av_d2q` does.

`Timestamp` pairs `ticks: i64` with a `timebase: Rational64`. `rescale_to` and `rescale_to_rnd` compute `ticks × a / b` in 128-bit arithmetic with explicit rounding modes, so conversions between clocks (90 kHz, 48 kHz, nanoseconds, 1/1001 frame rates) are exact and never overflow. `Timestamp::NONE` marks a missing timestamp.

`rescale_delta` carries the rounding remainder across successive audio packets, so long runs of resampled timestamps do not drift.

```rust
use ragdoll_core::{Rational64, Timestamp};

let pts = Timestamp::new(172_800 * 90_000, Rational64::new(1, 90_000)); // 48 hours at 90 kHz
assert_eq!(pts.to_nanos(), Some(172_800_000_000_000));
assert_eq!(pts.format_hms(), "48:00:00.000");
```

## Color

`Colorimetry` holds ITU-T H.273 (CICP) code points. The MP4 demuxer and muxer read and write it as `colr` (`nclx`) boxes, the H.264 encoder signals it in the VUI, and `ragdoll-pix` reads it when choosing a conversion matrix. `Chromaticities` provides the CIE xy primaries and white point for each `ColorPrimaries` value.

## Frames and buffers

- `AlignedBuffer`: 64-byte-aligned, zero-initialized, with 64 bytes of zeroed tail padding.
- `Plane`: a buffer plus width, height and stride.
- `VideoFrame`: up to three planes, a `PixelFormat`, `Colorimetry`, timestamp and picture type.
- `AudioFrame`: interleaved samples with rate, channel count, layout and sample format.
- `FramePool`: thread-safe recycling of `VideoFrame`s with frame-count and byte limits.

See [Memory model](/docs/architecture/memory/) for why these are shaped the way they are.

## Bit I/O

`BitReader` reads big-endian bit fields with a 64-bit cache refilled in one load, and decodes Exp-Golomb (`ue(v)`, `se(v)`) and Rice codes with a single count-leading-zeros instruction. `BitWriter` is the inverse. `unescape_rbsp` and `escape_rbsp` remove and insert H.264 / HEVC emulation-prevention bytes; the unescape path has NEON and AVX2 fast paths for long runs without `00 00 03`.

## Power

`PowerMode` selects a scheduling profile; `with_power_mode` applies one for the duration of a closure. `CpuTopology::detect()` reports logical, performance and efficiency core counts and cache sizes. `measure_hardware_metrics` wraps a closure and returns wall and CPU time, instructions, cycles, IPC, estimated energy and peak RSS. Instruction and cycle counts come from `proc_pid_rusage` and are only available on macOS (elsewhere they are `0`), and energy is a model estimate from cycles or CPU time, not a measurement. See [Power modes](/docs/power/).

## SIMD dispatch

Every kernel with a SIMD path asks `dispatch::neon()` or `dispatch::avx2()` before taking it. By default that is the best level the CPU supports; the `RAGDOLL_SIMD` environment variable (`scalar`, `neon` or `avx2`) forces a level instead, which is how CI runs the whole test suite on the scalar reference paths. The variable is read once, on first use, and naming a level the CPU does not support panics.

```rust
use ragdoll_core::dispatch::SimdDispatch;

println!("detected {}, using {}", SimdDispatch::detected().name(), SimdDispatch::active().name());
```

## Testing helpers

`testing::require_tool("ffmpeg")` and `testing::tool_succeeded(status, what)` make an interop test fail when a reference tool is missing or its command fails, so such tests never pass without testing anything. Setting `RAGDOLL_ALLOW_MISSING_TOOLS=1` turns those failures into skips.
