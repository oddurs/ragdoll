# Roadmap

Ragdoll is pre-1.0. This page describes what works today, what is being built now, and what is planned before the 1.0 release. Dates are not promised; each area ships when it passes the same verification as the rest of the codebase.

## Available today

- **Foundation.** 128-bit timebases and rescaling, CICP and Oklab colorimetry, 64-byte-aligned frame pools, bit I/O with Exp-Golomb and Rice coding, CRC-8/16/32.
- **Pixels.** YUV, NV12, RGB and Oklab conversion; 10-bit to 8-bit dithering; Lanczos-3, Spline36, Mitchell and bilinear scaling; PSNR, SSIM, MS-SSIM and VMAF-Lite.
- **Containers.** Zero-copy MP4, Matroska / WebM and MPEG-TS; Y4M, WAV / RF64, Netpbm, WebVTT and SubRip.
- **Codecs.** FLAC and PCM; H.264 Constrained Baseline encode and decode; the RGDI intermediate codec; AV1 bitstream inspection.
- **Pipeline and CLI.** GOP-parallel encoding with a bounded working set, stdin / stdout pipes, multi-track audio, video and subtitles re-timed with 128-bit arithmetic, TOML recipes, and the `probe`, `remux`, `transcode`, `extract`, `metrics`, `synth`, `bench` and `self-test` commands.

## In development

**Production H.264.** Full 4×4 and 8×8 residual coding, nine-mode intra 4×4 prediction, quarter-pel motion compensation, the in-loop deblocking filter, Main and High profiles with CABAC, the 8×8 transform, B-frame decoding, and CRF and VBV rate control.

## Planned for 1.0

| Area | Scope |
| :-- | :-- |
| **Audio** | AAC-LC and Opus encode and decode; a Kaiser-windowed polyphase resampler; 5.1 / 7.1 ↔ stereo remixing; EBU R128 loudness and true-peak normalization; native FLAC and Ogg containers with seek tables and tags. |
| **Editing** | Frame-accurate `ragdoll cut` and `ragdoll concat` that re-encode only the GOPs at each boundary and copy everything in between. |
| **Images and filters** | PNG and baseline JPEG; crop, pad, rotate, frame-rate conversion, overlay, and HDR-to-SDR tone mapping. |
| **Packaging** | `ragdoll package`: one command from a source file to a CMAF HLS and DASH bitrate ladder. |
| **x86_64** | AVX2 implementations of every NEON kernel, verified against the same scalar references. |
| **Library** | A small, stable facade (`Transcoder`, `Prober`, `Editor`, `Packager`) over the current crates. |
| **Hardening** | A malformed-bitstream fuzz corpus run in CI, with the requirement that no input causes a panic. |
| **Benchmarks** | A twelve-workload release suite with in-process FFmpeg comparisons and matched output quality. |

## Known limitations

- **No AVX2 kernels yet.** On `x86_64`, Ragdoll runs its scalar reference implementations. They are correct but slower.
- **Decoding is not yet bounded.** `transcode`, `extract` and `metrics` decode the entire input before processing it, so memory use grows with input length even though encoding is bounded.
- **H.264 compression.** The encoder falls back to `I_PCM` for blocks it cannot yet code with residuals, so output files are large.
- **Some options have no effect.** `remux --faststart`, `transcode --color`, and the recipe keys `start`, `duration` and `sample_rate` are accepted but not applied.
- **Unknown options are ignored** rather than rejected.
- **Piped transport streams.** `probe -` can report the wrong dimensions for an MPEG-TS stream read from stdin. Probing the same data from a file is correct.
- **Kernel benchmarks.** The FFmpeg side of the kernel comparison is not yet reproducible from the repository. See [Benchmarks](/docs/benchmarks/).
