## Problem

Teams that train or run vision models on video spend much of their pipeline decoding to RGB, resizing and normalizing on the CPU, then copying the result into PyTorch or JAX. Today that means FFmpeg (or a wrapper such as PyAV, decord or torchvision.io) and at least one extra copy per frame. Ragdoll already has the pieces that matter here: zero-copy demux, GOP-parallel H.264 decoding that is now bit-exact against FFmpeg (BUG-0060), fused scanline colour conversion and scaling, and a Rust SDK.

A Python package that turns `MP4 -> crop/resize/normalize -> tensor` into one call, with no copy at the boundary, is a narrow wedge where Ragdoll can be measurably better and where its current codec coverage (H.264) is enough to be useful.

Exposing a Python API and a C ABI is consistent with ADR-0006: that decision forbids Ragdoll calling C, not other languages calling Ragdoll.

## Architecture & SIMD Design

- A `ragdoll-py` crate (PyO3 + maturin) outside the default workspace build, so the core crates keep zero non-Rust dependencies.
- Frames exported through the DLPack protocol (`__dlpack__` / `__dlpack_device__`) from 64-byte-aligned `FramePool` buffers, as `uint8` HWC or normalized `float32` CHW.
- Fused kernel: YUV420 -> RGB -> resize -> per-channel normalize in one scanline pass (ADR-0007), so the full-resolution RGB frame is never materialized.
- Sampling API: decode every Nth frame or frames at given timestamps; decode only the GOPs containing requested frames.
- Bounded memory comes from BUG-0072's GOP-wave decoding, which this depends on.

## Acceptance criteria

- [ ] `pip install` builds the package from source; `ragdoll.read_frames(path, size=(224, 224), every=N)` returns tensors that `torch.from_dlpack` consumes with no copy (verified by pointer equality).
- [ ] Decoded RGB is checked against FFmpeg's decode plus a documented reference conversion, within a stated tolerance.
- [ ] A benchmark against PyAV and decord on the same inputs reports frames per second and peak RSS, generated by the QA scorecard (`0069`) rather than written by hand.
- [ ] Peak RSS is bounded by the memory budget for inputs of any length.
